# 创作画布控件与独立节点开发规范

本规范维护创作画布及已接入节点的实现边界；现有节点视觉与行为以 [前端与交互规范](FRONTEND_INTERACTION.md) 及其带版本的实现核对记录为依据。原生陈列与独立 Vue 陈列用于辅助检查，不代替真实节点。展厅、徽章旧 App Mode 保持原调用方式，ComfyTV 上游只读。

视觉与产品行为按 [前端与交互规范](FRONTEND_INTERACTION.md) 的任务表阅读；本文件只维护实现边界、复用与生命周期契约。

## 一、如何调整通用交互

1. 先查找现有实现和消费方，再决定修改。当前入口：`web/creative_button.mjs`、`web/creative_field.mjs`；宿主生命周期在 `web/creative_canvas_view.mjs`；样式限定 `.dae-creative`，保留已有 studio 视觉变体。
2. 通用层只负责焦点、禁用、校验、异步忙碌、事件和释放，不读取 app.graph、节点类型、模型名称、API、业务字段或其他节点内部属性。业务通过回调、参数和返回值注入。不得复制共享实现到节点目录再单独修改。
3. 优先使用现有接口；确需扩展时增加兼容的可选参数，并登记所有消费方。按钮异步回调必须返回 Promise；共享层管理临时 disabled/aria-busy，业务层负责请求与错误提示，不叠加另一套忙碌管理。
4. 现有原生面板通过 lease 接入：挂载时绑定，release/abandon 时清理监听和恢复属性/处理函数。绑定幂等；旧异步结果不能改写已释放或重新绑定的实例。不要在模块加载时批量扫描和改写全局控件。
5. 数字字段使用原生 min/max/step 和 validity；动态限制仍由业务提供。输入草稿与已提交值分离，非法输入不得写回业务状态；组合输入、键盘、失焦和外部值更新应列入有影响的变更验收。
6. 先在原生陈列显示变化，再在至少两个真实实例验证“一处修改共同生效、数据互不影响”。新增样式不得全局覆盖 input/button/select 或旧 App Mode。

## 二、如何新增独立功能节点

1. 使用稳定 `DAELAB.*` 标识，后端节点、API/服务、前端适配、数据模型和测试归所属仓库维护。当前 `DAELAB.MediaUpload`、`DAELAB.MaterialGroup`、`DAELAB.VideoEdit` 在本画布仓库；表格、分镜与 LibTV 业务节点在业务库。不得向画布添加业务生成依赖，不得修改或运行时导入 ComfyTV 上游实现，不替换其注册。
2. 推荐按职责分层：纯数据模型（解析/校验/迁移）、业务服务（请求/任务/结果）、面板（渲染/事件）、宿主适配（widget、序列化、挂载/释放）。小节点可保留少量文件，但职责不能混入通用控件。
3. 每个实例创建独立状态、DOM、订阅和取消句柄。禁止模块级可变“当前节点”承载业务数据。共享常量和纯函数可以复用；模块级集合仅用于有清理出口的生命周期管理。
4. 节点间使用声明的输入输出类型、稳定资产/记录 ID 和公开服务契约通信；不得访问另一节点的 DOM、私有属性、内部函数或依赖其布局/标题。现有历史桥接不作为新代码范例。
5. 复用共享按钮/字段，通过业务回调更新本节点 widget/model。参考 LibTV 的 creativeButtons/creativeFields 暴露方式；通用层不应为某个节点写条件分支。新增宿主适配需明示类型、面板所有权和 release，不在共享控件中增加节点识别。
6. 保存业务数据到明确的序列化结构，带版本及旧数据迁移；不保存 DOM、Promise、监听器、凭据或运行时忙碌状态。异步请求用实例/请求身份校验，删除或重载后取消或忽略旧结果。
7. 新增基础节点复用 `web/creative_panel_state.mjs` 的 Active/Bypass/Mute 行为；业务库继续复用自己的 App Mode 处理。新增画布支持类型使用 `docs/adapter-contract.md` 的注册接口并补测试。
   当前基础面板通过 100ms 检查节点 mode，同步 hidden/inert；停用时暂停音视频，恢复 Active 时还原原属性。画布面板借用／归还与节点执行模式是不同的生命周期，不将当前模式同步描述为无轮询。
8. 新增图标复用本地 Phosphor/Remix，保留许可证。测试样例不得包含凭据、私有路径或生产任务数据。

## 三、每次提交的验收与协作约定

- 记录：共享入口、消费方、公开契约、业务所有者、影响范围及不兼容项；修改范围跨模块时先更新 owning 文档再实施。
- 至少两个实例：修改 A 不影响 B；共享实现变化同时作用于二者。
- 覆盖有效/无效输入、禁用、异步成功/失败、重复点击、删除/释放、切换模式、保存/刷新恢复。检查现有业务联动，不仅断言 DOM 标记。
- 原生陈列 JSON 与真实节点使用同一实现；状态样例可使用无副作用的本地数据，但不得另写行为副本。
- 根据影响运行按钮/字段浏览器脚本和相关单元测试。旧模式检查写清是加载隔离、交互回归还是完整业务验收；模拟服务与真实生成结果分开报告。
- 提交前检查暂存 diff、依赖闭包与 `git diff --cached --check`。只提交本任务变更；共享文件中的其他任务修改分块保留。禁止为通过验证而执行未授权付费生成。

## 当前验收基线

原生 `examples/creative_canvas/Creative Canvas Controls.json`：26 个共享按钮、8 个真实共享字段及 5 个字段状态样例。现阶段已记录 15 项按钮检查、14 项字段/模式检查和 21 项相关 Node 测试。徽章/展厅仅完成加载、显示和隔离冒烟检查；不是完整业务回归，也未执行付费生成。此处为迁移前历史基线；本次独立仓库验收见 `../validation.md`。

本规范指导后续新增与修改，不意味着历史代码全部符合上述分层；历史耦合仅在授权范围内渐进处理。
